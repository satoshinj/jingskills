# 公众号长文排版契约

## 目标

排版首先解决移动端分神，不用装饰堆叠掩盖文章结构。视觉层级服务三种动作：让人停下、让人扫读、让人继续读。

## 三层结构

| 层级 | 用途 | 建议频率 |
|---|---|---|
| 锚点 | 章节标题、核心判断、结论 | 全文 3–5 处 |
| 标记 | 原文已经确认的完整关键判断 | 按母稿语义使用 |
| 容器 | 导读、章节标题、引用、数据或提示 | 按文章结构使用 |

不要把每句话都做成锚点。不要用空段落、连续 `<br>` 或大面积 padding 模拟章节。

## 长文最低结构

- 3000–8000 字通常使用 4–9 个章节。
- 第一屏需要一个明确判断或冲突，但不要重复公众号外标题。
- 三个以上章节可以提炼三项导读；导读不是完整目录。
- 章节标题必须推进判断，避免“背景”“分析”“总结”。
- 原文中的完整关键判断保留加粗；排版器新增下划线时不得拆开英文单词。
- 默认不生成金句卡；只有用户明确需要更强视觉锚点时，最多选择 1–2 处。
- 结尾按用户要求决定：只保留文章结论、加 END、保留原文署名，或完全无尾注。不得自动加入作者占位、二维码和互动引导。

## HTML 交付约束

- 干净正文是单个顶层 `<section>` 片段，不含 `html`、`head`、`body`、`script`。
- 样式使用内联 CSS；不依赖外部字体、样式表或运行时脚本。
- 不使用空 `<p>`、连续 `<br>`、`position:fixed`、`display:grid` 或横向溢出。
- 正文图片自适应且不强制放大小图；封面不嵌入正文首屏。
- 预览页可以有复制按钮，但复制区域只包含干净正文片段。

## 主题选择

- 观点、力量感、争议判断和行动号召：`jing-judgment`（Jing 判断）。
- 教程、步骤、工具盘点和行动指南：`jing-method`（Jing 方法）。
- 科技评论、专业判断和长篇解释：`jing-deepread`（Jing 深读）。

三套主题的完整规则见 [theme-library.md](theme-library.md)。先选阅读动作，再选主题。用户只说“排版单调”时，优先检查章节、段落长度、加粗判断和留白，不增加更多卡片与颜色。

## 正文配图

正文里的图由 `jing-writer` 按 `references/inline-illustrations.md` 生产（外部 skill `codex-image` 出图，落知识库素材区）。本 Skill 只消费：`wechat_images.py` 扫 `<img src>` 上传非 https 的本地图并重写为微信永久 URL，`render_article.py` 在还有未上传的图时报 `images are not uploaded yet`——这是正常中间态，按顺序补上传即可，不要把它当故障或手工改 HTML 绕过。

本 Skill 不生成正文配图。用户在排版阶段才提出要配图时，回到 `jing-writer` 定槽位再出图，不在排版环节临时插图——图的位置属于文章结构，不属于主题样式。

## 外部排版器

可以调用用户已经安装并选定的排版 Skill。使用 `isjiamu/gzh-design-skill`（skill 名 `gzh-design`，本机已安装）时把它视为独立的 AGPL-3.0 工具：读取并执行，不把其组件代码、主题文件或脚本复制进 jingskills。最终仍使用本 Skill 的本地交付门和草稿验收门。

### 什么时候交给它

- 用户点名要第三方主题、或明说要 `gzh-design` / "红白色系" / "摸鱼绿" 这类它注册的主题名。
- 自有三套主题都不契合题材，且用户想先看更多风格选项。

反之，用户没提第三方、或只说"排版单调"时，先按上面的自有主题流程处理，不要主动换排版器。

### 交接怎么做

本 Skill 的脚本只认 `--html <路径>`，不锁定渲染器：`wechat_images.py` 用正则扫 `<img src>` 并上传非 http(s) 的本地图，`wechat_draft.py` 直接提交给定 HTML。所以外部排版器的产物可以原样进管线：

1. 调用 `gzh-design` 完成排版，让它把 HTML 落到本地文件。
2. 图片上传、草稿写入、UTF-8 回读**全部仍走本 Skill 的脚本和门控**，顺序不变。
3. `wechat_draft.py --theme` 传外部主题标识，格式 `gzh-design:<主题英文标识>`（例如 `gzh-design:red-white`）。这个值只写进文章 frontmatter 的 `wechat_draft_theme`，是"这篇草稿用了哪套主题"的唯一审计记录——传错等于记错，重排时无法判断线上草稿是哪套样式。

### 边界

外部排版器只负责生成 HTML。它的预览、自检和评分都不能替代本 Skill 的手机预览确认、草稿写入确认和回读验收；它报告"排版完成"不等于草稿已保存。真机样式与预览不一致时，属于外部主题的问题就回到 `gzh-design` 修组件库，不要改 `jing-themes.json` 去追一套不属于自有主题的样式。
