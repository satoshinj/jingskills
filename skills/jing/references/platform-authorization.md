# 平台授权与确认

这是 `jing`、内容管线、`jing-wechat` 和 `jing-x-article` 的平台授权单一事实源。按当前任务的完整对话判断，不只看最后一条消息。

## 授权有效范围

- 对同一内容、账号、平台和动作的明确授权，覆盖同一任务的续做、纠错、验证和可恢复重试；用户撤回授权或范围发生实质变化时重新确认。
- “换这张封面，继续”等续做指令不会抹去已有草稿写入许可；“先停”“只看预览”等限制应立即遵从。
- 其他任务或平台的许可、已登录状态、草稿 ID、白名单和出口修复都不构成授权。一次明确点名多个平台并授权同一动作，可以覆盖这些平台，不能延伸到未点名的平台。
- 修复登录、网络或本地文件访问只恢复原授权，不增加公开发布、删除、费用或外发权限。需要执行前再次确认的操作仍按其规则确认。

## 动作级别

| 级别 | 范围 | 判定 |
|---|---|---|
| `local_only` | 只生成正文、HTML、封面、预览和交付包，不操作线上后台 | 用户限定本地预览，或当前任务尚无明确的平台草稿写入许可 |
| `draft_write` | 创建或更新指定平台的草稿，并完整回读验收 | 当前任务已明确平台和落点，例如“保存到微信草稿箱”“更新 X Article 草稿”“放进 X 后台” |
| 公开发布 | 不属于本管线及这两个平台 Skill | 草稿验收后另开明确发布任务，逐平台确认；不得由草稿许可推断 |

尚无草稿许可时，“推送到 X”“同步到两个平台”等模糊动作先做到本地产物，再询问是否写入指定平台草稿箱。完全没指名平台落点时只做本地，不额外发起平台选择。若完整对话已有有效许可，则按原许可续做，不因最后一句省略平台或落点而降级。

用户明确要求公开发布时，说明本管线最多做到已授权草稿；不得点击 `Publish`、调用发布或群发接口，也不得把草稿交付宣称为发布任务完成。

## 公众号两道确认门

公众号保留排版风格确认和草稿写入授权两道门。当前任务已确认的风格或预览、已授权的草稿动作不重复询问；风格实质改变时重新确认风格。两项都缺失时，在本地预览完成后一次展示，分别说明并一并确认。指定主题可作为风格选择依据，但不自动等于用户已看过并确认新预览；没有已确认预览时仍展示预览并确认。

Agent 的图片清单核对、结构检查和回读验收属于执行检查，不是额外的用户批准门。确认不能代替 QA，QA 也不能代替用户许可。
