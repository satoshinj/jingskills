# 正文配图

封面由 `jing-cover` 负责，本文只管**正文里的图**：示意图、结构图、场景插画、概念图。两条平台管线的消费端已经建好——`jing-wechat` 和 `jing-x-article` 的 `prepare_article.py` 都会解析 Markdown 图片嵌入并算出插入位置——**缺的只是生成图片文件本身**。

## 触发门控

正文配图默认不做。只在用户明确要求配图时才进这条流程，且**先报额度成本再动手**。

生成器是外部 skill `codex-image`（走 codex 订阅额度，不用 `OPENAI_API_KEY`、不计 API 费用），但额度和写代码共用同一个 5h / 7d 窗口：实测每张约占 5h 窗口的 2%。所以一篇配 5 张图 ≈ 吃掉当前 5h 窗口的 10%。报出张数和大致占比，用户确认后再生成。

用户没提配图时不要主动加。文章"看起来空"不是配图的理由——先检查章节、段落长度和加粗判断。

## 先定槽位，再生成

顺序不能颠倒：**图是为已经定稿的判断服务的，不是反过来**。写作阶段不让图片风格改动事实和核心判断。

1. 母稿已通过 `article_check.py`，判断和事实都定了。
2. 逐段定槽位：这一段的**读者卡点**是什么，一张图能不能解决。解决不了就不放图。宁可 2 张有用的，不要 6 张装饰的。
3. 每个槽位写清三件事：位置（在哪一段之后）、要解释的那一件事、图注。

槽位在 Markdown 里必须**独占一段**：

```markdown
上一段正文结束。

![用一句话说清这张图在解释什么](<vault>/01-Projects（项目）/<项目>/配图/2026-07-30-主题/01-三层结构.png)

下一段正文开始。
```

图片混在段落中间时 `jing-x-article` 的 `prepare_article.py` 直接失败——回来改 Markdown，不要到编辑器里凑。

## 落盘位置与命名

存进知识库素材区，与封面平级：

```
01-Projects（项目）/<项目>/配图/
```

文件名用 `<两位序号>-<短标识>.png`（如 `01-三层结构.png`）。序号按正文出现顺序，因为 `jing-x-article` 交付包的 `images` 清单是按正文顺序编号的，序号对不上时人工插图会插错位置。

## 生成

提示词按 `codex-image` 的 `references/prompt-recipes.md` 写成结构化 spec（用途 → 主体 → 细节 → 约束），一张图一个提示词文件，放 scratchpad 避免 shell 转义。一次调用出一张，批量就循环。

```bash
python ~/.claude/skills/codex-image/scripts/codex_image.py \
  --out "<绝对路径>/01-三层结构.png" \
  --prompt-file "<scratchpad>/prompt-01.txt" \
  --size "1536x1024"
```

约束写进提示词：

- **不要在图里放需要精确排版的中文文字**。模型画中文字形不可靠，图注走 Markdown 的 alt，不进图。少量英文标签可以。
- 同一篇文章的所有配图共用一套视觉语言（配色、线条、留白），和封面的视觉母题一致，不要一张扁平插画一张 3D 渲染。
- 说明性的图优先结构清楚，不追求画面华丽。

## 验收（必做）

脚本返回 JSON，**不要只看它说成功**：

1. `ok: true` 且 `width/height` 合理。
2. **把图读出来肉眼看**：主体对不对、有没有混进乱码文字、风格和其他配图是否一致。
3. 不合格时重试**最多一次**，仍不行就换提示词思路或问用户，别空转烧额度。

`ok: false` 时看 `error` 和 `codex_stdout_tail`：没产出或模型在反问 → 提示词更明确；不是有效 PNG 或尺寸极小 → 模型可能用代码画的，强化"严禁代码绘制"再试。

## 交给平台

生成完只是本地素材，两条管线各自照原有门控走，本流程不绕过任何一道：

- `jing-wechat`：`wechat_images.py` 扫 `<img src>` 上传非 https 的本地图并重写为微信 URL。`render_article.py` 会用 `images are not uploaded yet` 拦住没上传的图——这是正常的中间态，不是故障。
- `jing-x-article`：图进交付包的 `images` 清单（`order` / `path` / `after_block` / `after_text` / `alt`）。X 没有按块插图的接口，**由人按清单手工插**，块数核对必须在插图之前做完。详见 `jing-x-article` 的 `x-editor-contract.md`。

## 译介稿

译介稿**不使用原文的配图或截图**，除非授权明确覆盖图片。自己生成的示意图可以用，但只能解释原文已有的论点，不得引入原文没有的事实或数据。授权没放行时照常只做本地产物。

## 不做什么

- 不用图掩盖论证空洞。一段话说不清的事，配图也说不清。
- 不生成需要精确文字排版的图（海报、带大段文案的卡片）——那不是本流程的范围。
- 不因为图好看就调整正文事实或结论顺序。
- 不把配图当封面用，尺寸和构图要求不同（封面走 `jing-cover`）。
