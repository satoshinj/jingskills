# Jing 本地知识库写作管道

下列路径都相对于已确认的知识库根目录 `<vault>`。兼容知识库应包含 `.jing-obsidian.json`，或至少同时存在 `01-Projects（项目）/`、`02-Areas（资产）/`、`03-Resources（资源）/` 与 `05-Skills（技能）/`（PARA 布局）。不要依赖知识库名称。

`Clippings/` 若存在则视为**只读**：Web Clipper 原件不得改写、移动或删除。

## 文件职责

| 路径 | 内容 |
|---|---|
| `00-Inbox（灵感库）/` | 等待人判断是否值得推进的选题与剪藏审核卡 |
| `03-Resources（资源）/<主题>/` | 外部原文、网页、X、视频与附件。同一份资料可被多个项目引用，**不在项目目录里留第二份副本** |
| `02-Areas（资产）/<主题>/概览.md` | 可长期复用的判断。优先更新既有页，不一事一页 |
| `04-Archive（归档）/<主题>/` | 用户确认发布后的正式稿归档 |
| `05-Skills（技能）/内容生产/模板/` | 成稿包、调研包、草稿与笔记模板 |

**一篇内容就是一个项目。** 决定推进后建 `01-Projects（项目）/<YYYY-MM-DD-主题>/`，它的全部工作产物都留在里面：

| 项目目录内 | 内容 |
|---|---|
| `成稿包.md` | 问题、判断、事实边界、个人材料、情绪曲线 |
| `调研.md` | 事实清单、来源索引、数据快照、结构研究 |
| `<标题>.md` | 当前有效的完整草稿（一个主题只留一份） |
| `封面/` | 封面任务包、无字底图、公众号与 X 成品和清单 |
| `配图/` | 正文里的示意图与插画，按正文顺序编号。契约见 [inline-illustrations.md](inline-illustrations.md) |

项目目录内不再增加分类层——六大分类下只保留「主题」一层是知识库的既有约定，项目内部的 `封面/`、`配图/` 是产出而非分类。

## 正常流转

外部资料先进入资料区并生成审核卡。人工选择“仅保留为写作素材”后，系统自动建立成稿包，而不是修改原始资料。

当用户直接从一个已经沉淀为长期知识的角度发起写作时，也建立新的成稿包，并同时链接长期知识、审核卡和原始来源。

写作任务继续推进时：

1. 丰富成稿包中的问题、判断、情绪和真实材料。
2. 建立主题调研目录和事实清单。
3. 生成一份当前草稿。
4. 完成检查和用户确认。
5. 需要封面时，把正文、成稿包和一句话判断交给 `jing-cover`，生成双平台素材。
6. 用户明确要求发布或归档时，才写入发布区。
7. 将新增的长期认识回写为独立知识，不把整篇文章复制进知识区。

## 版本规则

- 原始资料保持原样。
- 审核卡只记录判断、动作和结果文件。
- 成稿包保存写作依据，不塞入完整正文。
- 草稿目录每个主题只保留一份当前有效版本；需要保留历史时依赖版本记录或移入归档。
- 用户个人笔记和明确手写内容永远保留。

## 命名

- 成稿包：`YYYY-MM-DD-主题.md`
- 调研目录：`YYYY-MM-DD-主题/`
- 草稿：`YYYY-MM-DD-标题.md`
- 文件名使用读者能理解的中文主题，不使用随机编号代替语义。

## 最小触发方式

用户只需说“把这个 idea 写成文章”并指出资料、审核卡或主题。系统负责发现上下游材料、创建缺少的文件和完成检查。若没有兼容知识库，完整管线先交给 `jing-obsidian` 初始化；用户只要一次性文章时可以在当前工作区降级交付，但必须明确不会自动回流长期知识。
