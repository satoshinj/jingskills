# 环境与能力

哪些 Skill 现在真能跑完、哪些会停在半路，取决于宿主装了什么、配了什么凭据。本页记录**实测**结论与自查方法，不写没验证过的推断。

最后实测：2026-07-30（macOS 26 / Apple Silicon）。

## Python 依赖

脚本一律用 `python3` 调用，所以依赖必须装在**默认 `python3`** 上，不是某个 venv 里。

需要：`pillow`（`jing-cover` / `jing-x-article` / `jing-broll`）、`google-genai`（`jing-broll` 的 Gemini 路径）、`httpx`（`jing-broll` 的 fal 路径）。`certifi` 由脚本自动接线。

自查：

```bash
for m in PIL google.genai httpx; do python3 -c "import $m" && echo "$m OK" || echo "$m MISSING"; done
```

macOS 上若 `python3` 指向 uv 托管的解释器，它是 externally managed，`pip install --user` 会被 PEP 668 拒绝。可行装法：

```bash
python3 -m pip install --user --break-system-packages pillow httpx google-genai
```

## 视频三个环节

`jing-broll` 的三个环节后端独立，**不共用一个 key，也不同时可用**。默认组合零 API 费用：

| 环节 | 默认 | 降级 |
|---|---|---|
| 静帧 | `codex-image`（codex 订阅额度） | Gemini 图片模型（需 API 付费层） |
| 画面 | `hyperframes`（零生成成本、确定性） | Gemini 首尾帧插值（需 API 付费层） |
| 旁白 | Gemini TTS（**免费层可用**） | macOS `say -v Eddy -o out.aiff` + ffmpeg 转码 |

只有用户点名要 AI 运镜时才需要付费层。

## Gemini API：免费层 ≠ Pro 会员

这是最容易踩的一条。**Gemini Pro / Advanced 是消费者 App 订阅，不含任何 API 额度。** AI Studio 生成的 key 默认在免费层，需要给对应 project 单独开启结算才升到付费层。

免费层实测（2026-07-30）：

| 模型 | 结果 |
|---|---|
| `gemini-3.1-flash-tts-preview` | ✅ 可用 |
| `gemini-3-pro-image` | ❌ `429 RESOURCE_EXHAUSTED`，`limit: 0` |
| `gemini-3.1-flash-image` | ❌ 同上 |
| `gemini-2.5-flash-image` | ❌ 同上 |
| `gemini-omni-flash-preview`（视频） | ❌ 同上 |
| `veo-3.1-fast-generate-preview` | ❌ 配额耗尽 |

`limit: 0` 的意思是免费层对该模型根本没有配额，不是「用完了等等再试」。模型出现在 `models` 列表里**不代表有权调用**。

自查某个 key 能调什么：

```bash
curl -s "https://generativelanguage.googleapis.com/v1beta/models?key=$GEMINI_API_KEY" \
  | python3 -c "import json,sys; print(len(json.load(sys.stdin)['models']),'models')"
```

列表通了只说明 key 有效。真实权限只能靠实际调用一次来确认。

## 凭据放哪

放一个 600 权限的独立文件，从 `~/.zshenv` 加载——agent 跑脚本用的非交互 shell 只 source 它：

```bash
umask 177
printf "export GEMINI_API_KEY='...'\n" > ~/.secrets.zsh
printf '\n[[ -f "$HOME/.secrets.zsh" ]] && source "$HOME/.secrets.zsh"\n' >> ~/.zshenv
```

**密钥不进仓库、不进知识库、不进可见命令。** 已经出现在聊天记录或命令历史里的 key 视为已泄漏，去服务商后台轮换。

agent 会话的环境是启动时的快照：刚配好的变量当前会话可能看不见，命令里显式 source 一次。

## 公众号为什么最难通

`jing-wechat` 到草稿箱需要三样，缺一不可：

1. `WECHAT_APPID` / `WECHAT_SECRET`
2. `~/.jing-wechat/config.yaml`
3. `~/.jing-wechat/fixed-egress.json`——**固定出口**

第 3 条是微信的 IP 白名单机制决定的：脚本取 token 前先核对当前公网地址，不符就原地停止，不会静默切回动态地址。所以需要一台固定公网 IP 的机器，并把该 IP 加进公众号后台白名单。微信报 `40164` 就是白名单不符。

另外：`jing-wechat` **按设计不发布也不群发**，终点永远是草稿箱，最后一步由人在后台点。

## 一次跑完的自查

```bash
# 二进制
for b in ffmpeg ffprobe python3 codex grok npx; do command -v $b >/dev/null && echo "$b OK" || echo "$b MISSING"; done
# Python
for m in PIL google.genai httpx; do python3 -c "import $m" 2>/dev/null && echo "$m OK" || echo "$m MISSING"; done
# 凭据
for v in GEMINI_API_KEY FAL_KEY WECHAT_APPID WECHAT_SECRET; do [ -n "${!v}" ] 2>/dev/null && echo "$v set" || echo "$v NOT_SET"; done
# broll 自带自检
bash skills/jing-broll/scripts/check_setup.sh
# 结构与打包
bash tools/build.sh
```
